# 通信协议

Mythclass 里所有端之间怎么说话，都写在这儿。

---

## 一、总览

三方：**教师端**、**服务端**、**客户端**。

```
教师端 ──HTTPS/REST──▶ 服务端 ◀──HTTPS/REST── 客户端
   │                     │                      │
   └──── WebSocket ──────┴──── WebSocket ───────┘
```

- **REST** 管「正经事」：注册、登录、绑定、查记录、改设置。
- **WebSocket** 管「实时事」：屏幕帧、鼠标键盘、命令、心跳、信令。
- 两端都连**同一个服务端**才能互相看见。这条是硬规矩。

---

## 二、消息格式

WebSocket 走 Socket.IO v4，底层是 Engine.IO v4。

一条事件长这样（Engine.IO 帧 `42` + JSON 数组）：

```
42["command",{"clientId":7,"command":"lock","args":{},"requestId":"1719..."}]
```

| 前缀 | 意思 |
|---|---|
| `0` | Engine.IO 握手（服务端下发 sid） |
| `2` / `3` | ping / pong |
| `40` | Socket.IO CONNECT（客户端发起，带 auth） |
| `41` | Socket.IO DISCONNECT |
| `42` | 事件 |
| `44` | CONNECT 失败 |

REST 一律 JSON，字段用 camelCase，时间用 `YYYY-MM-DD HH:MM:SS`（本地时间，秒级）。

## 三、握手与鉴权

### 教师端

```js
const socket = io(server, {
  path: '/socket.io',
  auth: { token: '<teacher_jwt>' },
});
```

### 客户端

```
连接 wss://mythclassapi.ryokuryuneko.top/socket.io/?EIO=4&transport=websocket
← 0{"sid":"...","pingInterval":25000,"pingTimeout":20000}
→ 40{"token":"<client_jwt>"}
← 40{"sid":"..."}      成功
← 44{"message":"..."}  失败，等会儿重连
```

三套凭证分开，互不通用：

| 谁 | 表 | Header / auth | 密钥 | 有效期 |
|---|---|---|---|---|
| 教师端 | `users` | `Authorization: Bearer <jwt>` | `JWT_SECRET` | 7 天 |
| 客户端 | `clients` | `Authorization: Bearer <jwt>` | `JWT_SECRET` | 365 天 |
| Admin | `admins` | `Authorization: Admin-Bearer <jwt>` | `ADMIN_JWT_SECRET` | 1 小时 |

教师端 JWT 载荷：

```json
{ "uid": 12, "username": "teacher", "tv": 3, "role": "teacher", "iat": 0, "exp": 0 }
```

`tv` 是 `token_version`。封禁、解封、改密码都会把它加一，于是老 token 立刻作废。

## 四、消息类型

### 1. `register` — 客户端注册

REST：`POST /api/client/register`

```json
{
  "clientUid": "MYTH-3F2A-9C21-B4D8",
  "name": "高一(3)班一体机",
  "os": "Windows 10 10.0.19045",
  "version": "1.0.0"
}
```

回：

```json
{
  "token": "<client_jwt>",
  "client": { "id": 7, "clientUid": "MYTH-...", "name": "..." },
  "server": { "official": "wss://mythclassapi.ryokuryuneko.top", "relayEnabled": true }
}
```

服务端连上后也会通过 WebSocket 推一条 `registered`：

```json
{ "clientId": 7, "relayEnabled": true }
```

### 2. `bind` — 教师端绑定客户端

REST：`POST /api/auth/bind`

```json
{ "clientUid": "MYTH-3F2A-9C21-B4D8", "name": "高一(3)班一体机" }
```

绑定成功后，教师端可以 `watch` 这台机器：

```json
→ 42["watch",{"clientId":7}]
← ack {"ok":true,"online":true}
```

服务端会核对 `bindings` 表。不是自己的机器，`ack` 回 `{"ok":false,"error":"NOT_BOUND"}`。

### 3. `offer` / `answer` / `ice` — WebRTC 信令

P2P 直连用。服务端只转发，不看内容。

```json
→ 42["offer",  {"clientId":7,"sdp":"v=0\r\no=- ..."}]
← 42["offer",  {"clientId":7,"sdp":"..."}]
→ 42["answer", {"clientId":7,"sdp":"..."}]
→ 42["ice",    {"clientId":7,"candidate":"candidate:..."}]
```

打洞失败就退回中继——也就是直接走服务端转发的 `screen_frame` / `control_event`。

### 4. `screen_frame` — 屏幕帧

客户端 → 老师（服务端转发）。

```json
{
  "clientId": 7,
  "data": "data:image/jpeg;base64,/9j/4AAQ...",
  "width": 1280,
  "height": 720,
  "ts": 1719300000000
}
```

约定：

- 只在老师 `watch` 之后才推
- 默认 12 fps、JPEG 质量 60，宽超过 1600 先缩
- 老师发 `command: screen_start` 开流，`screen_stop` 关流
- 没人看就别推（省一体机的性能）

### 5. `control_event` — 鼠标键盘

老师 → 客户端。坐标是**归一化**的，跟分辨率无关。

```json
{ "clientId": 7, "event": { "type": "mousemove", "x": 0.412, "y": 0.733 } }
{ "clientId": 7, "event": { "type": "mousedown", "button": "left", "x": 0.412, "y": 0.733 } }
{ "clientId": 7, "event": { "type": "mouseup",   "button": "left" } }
{ "clientId": 7, "event": { "type": "key", "key": "Enter", "code": "Enter" } }
```

`x`、`y` 都是 0~1。客户端自己乘屏幕宽高。

移动事件教师端做了 50 ms 节流，别把网络灌满。

### 6. `audio_info` — 音频信息

客户端 → 老师。

```json
{
  "clientId": 7,
  "items": [
    { "processName": "chrome.exe", "title": "哔哩哔哩", "volume": 62, "state": "playing" }
  ]
}
```

`state` 取值：`playing` / `muted` / `idle`。`idle` 的不上报。

### 7. `file_log` — 文件修改记录

客户端 → 老师（同时走 REST 落库）。

```json
{
  "clientId": 7,
  "logs": [
    {
      "timestamp": "2025-06-25 14:32:08",
      "operation": "modified",
      "filePath": "C:\\Users\\Public\\Desktop\\作业.docx",
      "fileSize": 20480
    }
  ]
}
```

`operation` 取值：`created` / `modified` / `deleted` / `moved` / `renamed`。

REST 批量上报：`POST /api/client/file-logs`，体是 `{ "logs": [...] }`。同一文件 2 秒内的重复事件会被客户端合并。

### 8. `command` — 教师端下发命令

```json
{
  "clientId": 7,
  "command": "message",
  "args": { "text": "下课把窗关上" },
  "requestId": "1719300000123",
  "from": { "userId": 12, "username": "teacher" }
}
```

| command | args | 说明 |
|---|---|---|
| `screen_start` | `{fps, quality}` | 开屏幕流 |
| `screen_stop` | — | 关屏幕流 |
| `lock` / `unlock` | — | 锁屏 / 解锁提示 |
| `shutdown` / `reboot` / `logout` | — | 关机 / 重启 / 注销 |
| `message` | `{text, title}` | 弹窗通知 |
| `open_url` | `{url}` | 开网页 |
| `open_app` | `{path}` | 开程序 |
| `file_distribute` | `{url, path}` | 分发文件 |
| `screen_broadcast` | `{url}` | 屏幕广播 |
| `net_ban` | `{enable}` | 掐网 / 放网（要管理员权限） |

老师侧的 ack 只表示「服务端有没有把它递给客户端」，不代表客户端执行成功：

```json
{ "ok": true, "delivered": true }
```

真正的执行结果看 `command_result`。

### 9. `command_result` — 执行结果

客户端 → 老师。

```json
{
  "clientId": 7,
  "requestId": "1719300000123",
  "command": "message",
  "ok": true,
  "output": "弹窗已经推过去了",
  "at": "2025-06-25T14:32:11.204Z"
}
```

### 10. `heartbeat` — 心跳

```
→ 42["heartbeat"]
← 42["heartbeat:ack",{"t":1719300000123}]
```

客户端每 20 秒一次，服务端顺手刷新 `clients.last_seen`。

另有 REST 心跳 `POST /api/client/heartbeat`（每 15 秒，跟上报共用一个循环）。两条路都留，WebSocket 断了 REST 还能撑。

### 11. `client:presence` — 在线状态

服务端 → 老师。

单条：

```json
{ "clientId": 7, "online": true }
```

刚连上时批量推一次：

```json
{ "batch": [ { "clientId": 7, "online": true }, { "clientId": 9, "online": false } ] }
```

### 12. `settings:update` — 策略同步

老师改完保留策略，服务端推给客户端，客户端存本地并立即生效。

```json
{ "settings": { "maxLogCount": 5000, "maxLogSize": 209715200 } }
```

### 13. `force:logout` — 强踢

封禁、删号、改密码时，服务端给教师端所有连接发这个，然后断开：

```json
{ "reason": "USER_BANNED" }
```

原因：`USER_BANNED` / `TOKEN_REVOKED` / `USER_DELETED`。

## 五、连接流程

### 首次连接

```
1. 客户端起来，算 client_uid，POST /api/client/register 拿 token
2. 客户端连 WebSocket，服务端把它塞进房间 client:<id>
3. 老师登录，POST /api/auth/bind 填 client_uid
4. 老师进控制台，emit watch {clientId}
5. 服务端核对 bindings，准了才让进房间
6. 老师点「开始看」→ command screen_start → 客户端开始推 screen_frame
```

### P2P 直连（同局域网）

```
1. 老师在房间内 emit offer（带 SDP）
2. 客户端回 answer
3. 双方互发 ice
4. 通道打通 → 屏幕帧和控制事件直接走 P2P，不占服务端带宽
5. 用上次记住的教师端 IP 优先试直连，省一次信令往返
```

### 中继转发

P2P 打不通（跨网、NAT 太严格）就走服务端：

```
客户端 ──screen_frame──▶ 服务端 ──▶ 老师
老师   ──control_event──▶ 服务端 ──▶ 客户端
```

服务端用 Socket.IO 房间广播，`socket.to(room)` 排除发送者自己。

中继流量全由服务端扛，所以 `relayEnabled` 默认为 `true`，但同一局域网会优先走 P2P。

## 六、REST 接口速查

### 教师端 `/api/auth`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/registration-status` | 注册开关 |
| POST | `/register` | 注册 |
| POST | `/login` | 登录，回 token |
| GET | `/me` | 当前用户 |
| POST | `/change-password` | 改密码（会让所有 token 失效） |
| GET | `/clients` | 已绑定客户端 |
| POST | `/bind` | 绑定 |
| PUT | `/clients/:id` | 改名 |
| DELETE | `/clients/:id` | 解绑 |
| GET | `/clients/:id/info` | 详情 |
| GET | `/clients/:id/file-logs` | 文件记录（`limit/offset/q/operation`） |
| DELETE | `/clients/:id/file-logs` | 清空记录 |
| GET | `/clients/:id/audio-logs` | 音频历史 |
| GET / PUT | `/clients/:id/settings` | 保留策略 |
| POST | `/clients/:id/command` | 下发命令（REST 兜底） |

### 客户端 `/api/client`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/register` | 注册 |
| GET | `/config` | 拉策略 |
| POST | `/heartbeat` | 心跳 |
| POST | `/file-logs` | 批量上报文件记录 |
| POST | `/audio-info` | 上报音频 |
| POST | `/command-result` | 回执行结果 |

### Admin `/api/admin`

见 [Admin后台使用说明.md](Admin后台使用说明.md)。

## 七、安全

- **传输**：全程 TLS。Cloudflare 那段是 HTTPS/WSS，隧道内是加密出站。
- **鉴权**：JWT，三套密钥分开。教师端和 Admin 的密钥绝不相同。
- **越权**：任何带 `clientId` 的操作，服务端都先查 `bindings`。老师看不到别人的机器。
- **封禁即时生效**：`token_version` 机制 + `force:logout` 强踢。
- **初始化令牌**：Admin 的 setup token 只躺在服务端 `data/admin-setup-token.txt`，不通过任何接口下发内容，用掉即销毁。
- **消息签名**：当前没做逐条签名。内网直连场景够用；真要上签名，建议给 `command` 加个 HMAC，密钥从 JWT 派生。

## 八、WebSocket 注意事项

### EdgeOne

- **只支持 HTTP/1.1 的 WebSocket**，不支持 HTTP/2。
- 最大连接超时 **300 秒**。要去控制台：站点加速 → 网络优化 → 打开 WebSocket 开关，并设置最大连接超时（建议 300 秒）。
- 到了 300 秒会被服务端断开。教师端已经做了自动重连，断了会自己接回来。客户端也一样。

### Cloudflare Tunnel

- WebSocket 完全支持，不用额外配置。
- 长时间没数据可能被中间设备掐掉，所以两端都保持 20 秒一次的心跳。
- `originRequest.keepAliveTimeout` 建议 90 秒。

### 断线重连

| 端 | 策略 |
|---|---|
| 客户端 | 2 秒起步指数退避，最多 60 秒；重连后重新 `hello` |
| 教师端 | 1.2 秒起步，最多 8 秒 |

|---|---|---|

| `watch` / `unwatch` | 教师端 → 服务端 | WS |
| `offer` / `answer` / `ice` | 双向 | WS |
| `screen_frame` | 客户端 → 教师端 | WS |
| `control_event` | 教师端 → 客户端 | WS |
| `audio_info` | 客户端 → 教师端 | WS |
| `file_log` | 客户端 → 教师端 | WS |
| `command` | 教师端 → 客户端 | WS |
| `command_result` | 客户端 → 教师端 | WS |
| `heartbeat` / `heartbeat:ack` | 双向 | WS |
| `client:presence` | 服务端 → 教师端 | WS |
| `settings:update` | 服务端 → 客户端 | WS |
| `force:logout` | 服务端 → 教师端 | WS |
