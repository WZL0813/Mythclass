# 交付与更新清单

## 规则（主人定的）

**每次做完改动，回复末尾必须写清「主人要更新哪些端」** ——
客户端 / 教师端 / 服务器，三边逐一列出：

- 要不要更新（要 / 不要）
- 怎么更新（装哪个包、还是 git pull + 重启、还是重新部署）
- **怎么验证**（给一个能自己确认的标记，不要只说「更新一下」）

## 三边各自的版本标记

| 端 | 怎么看版本 |
|---|---|
| **客户端** | 托盘右键 → **状态**（里面有「版本：vX.Y.Z」和「本地网页：http://…」）；<br>或命令行 `MythclassClient.exe --status` |
| **教师端** | 页面上没有版本号 —— 认**功能**：某个新按钮/新对话框出现了就是更新到了 |
| **服务器** | 浏览器打开 `<服务端地址>/api/meta` → 看 `version` 和 `features` 列表；<br>缺哪个 feature 就是还没更新 |

## 常见组合

| 改动类型 | 客户端 | 教师端 | 服务器 |
|---|---|---|---|
| 只在客户端里（画面、通知窗口、托盘） | **要** | 不要 | 不要 |
| 只在教师端界面（布局、对话框、按钮） | 不要 | **要**（重新部署 EdgeOne） | 不要 |
| 服务端接口/字段（如 lan-key、same-network） | 不要 | 不要 | **要**（git pull + 重启） |
| 跨两端（如带密钥的直连链接） | **要** | **要** | **要** |

服务端更新后数据库不用手改：启动日志会打印补了哪些列（例如
`[Mythclass] clients 表补了 lan_key 列`）。
